# 实验总结
1. 维护 sys_get_time, sys_mmap, sys_munmap, sys_spawn 和 stride 调度算法
2. sys_linkat 和 sys_unlinkat: 为 easy-fs 的 Inode 添加 link 和 unlink 方法
    - link: 通过 old_name 找到 inode_id, 在 root_inode 中添加一个新的 DirEntry (new_name, inode_id)
    - unlink: 通过 name 找到 inode_id, 再通过 inode_id 计算链接数。在 root_inode 中删除对应的 DirEntry。如果链接数为 1，还需要删除对应的 inode 和回收数据块，注意需要提前获取 inode，防止发生死锁
3. sys_stat: 由于通过提供的 fd 得到的对象一定实现了 File trait, 故为 File trait 增加了 stat 方法。提供默认实现，并对 OSInode 的 stat 方法进行了重写，主要通过对 Inode 的方法扩展获得各项信息

# 简答题
## ch6
### 在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？
它是整个文件系统的根目录，所有需要对文件的操作都需要通过它来查找。如果损坏，系统将无法找到任何文件。

## ch7
### 举出使用 pipe 的一个实际应用的例子。
tips:
- 想想你平时咋使用 linux terminal 的？
- 如何使用 cat 和 wc 完成一个文件的行数统计？

```bash
cat file | wc -l
```
cat 将标准输出重定向到 pipe 的写端；wc 将标准输入重定向到 pipe 的读端。

### 如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐，请设计一个更易用的多进程通信机制。
无需两两建立管道，而是为每个进程建立一个接收缓冲区，其他进程可以通过系统调用将数据写入指定进程的接收缓冲区。
而每个进程可以通过系统调用从自己的接收缓冲区中读取数据。
